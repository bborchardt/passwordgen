Password Generator
==================
A simple web app that can be used to translate something you can remember to a website password. Useful for web sites that have overly restrictive password rules (such a limited password length or no support for special characters).

Everything happens in your browser. Nothing is stored and nothing is sent anywhere, so the same input always gives you the same password on any machine, with no vault to sync or lose.

Usage
-----
Open `web/index.html`, type the phrase you want to derive from, pick a length, and generate.

Passwords contain only letters and digits (`A-Z`, `a-z`, `0-9`) by design — the point is to satisfy sites that reject symbols. Sites that *require* a symbol are not currently supported.

Running the tests
-----------------
Requires Node 18 or newer. No dependencies to install.

    npm test

`test/v1-vectors.json` holds passwords generated by the original implementation. They are the guarantee that a change has not altered a password someone has already set on a real site — if that suite goes red, the derivation moved and existing passwords broke.

Deploying
---------
The app is static files; serve the `web/` directory with any web server.

**Serve it over HTTPS.** The entire security of this tool rests on your browser running exactly this code. Over plain HTTP anyone on the network can replace the scripts with a version that keeps a copy of your passphrase, and nothing in the page can prevent that.

The page ships a Content Security Policy that denies it any means of sending data out (`connect-src 'none'`, `form-action 'none'`), so its "nothing leaves your browser" claim can be checked rather than taken on faith. Two directives cannot be set from a `<meta>` tag and should be sent as response headers:

    Content-Security-Policy: frame-ancestors 'none'
    Strict-Transport-Security: max-age=63072000

Known limitations
-----------------
The derivation is unchanged from the original and has real weaknesses. Fixing any of them changes the passwords it produces, so they are deferred to a v2 that will run alongside v1 with a way to choose between them and migrate:

- **The same passphrase gives the same password on every site.** Nothing binds a password to a particular site, so one breached site exposes the rest unless you manually vary what you type.
- **The salt is a single constant shared by every user**, and is public in the source, so it does not do a salt's job of making precomputed attacks unprofitable.
- **Two inputs can collide.** When a result fails the character-mix check the tool retries with `1` appended to your input, which makes input `X` and input `X1` produce the same password. This happens for roughly 43% of inputs at the default length of 12.
- **PBKDF2 at 100,000 iterations is below current guidance** (OWASP's floor for PBKDF2-SHA256 is 600,000) and is comparatively cheap to attack with a GPU.
- **There is no version marker**, so nothing records which parameters produced a given password.
